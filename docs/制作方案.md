## 一、我理解的目标

1. 玩家和主持人**不下载任何文件**，浏览器打开 Foundry 网址就能听到角色语音
2. 合成压力**按配置**决定交给哪台电脑（而不是永远压在同一台）
3. 声音质量优先：不变调（已做）、情绪靠参考音换声线（已做）、AI 判语气/润色/选立绘（受 LLM 制约）
4. 长期可分发：别人拿到模块也能用（引擎需单独分发）

## 三、硬约束（不可绕过，必须承认）

1. **合成必须发生在装有引擎的机器上**（GPT-SoVITS 16.3GB + GPU）。
   → "零安装"与"多机分散"**不能同时对所有机器成立**：
   - 想人人零安装 → 合成集中在**服务器**（或某台常开机器）
   - 想把压力挪给某台电脑 → **那台必须装引擎**
2. **浏览器 HTTPS 页面无法直连 `http://<IP>:9881`**（混合内容拦截）→ 远程合成只能：
   - 走 **socket 代理**（Foundry 服务器转发，现有 ✓），或
   - 走 Foundry 服务器的 **HTTP 反向代理**（需在服务器前置 nginx/caddy，可另配 HTTPS）
3. **socket 消息有体积限制** → 大音频必须走"文件落盘 + 静态路径"（现有 `engine/audio_export` → `/modules/...` ✓ 已验证）

## 四、三种可选架构（请选一个方向）

### 方案 A：服务器集中合成（零安装最大化）
```
[服务器] Foundry(30000) + 引擎(9881, CUDA)   ← 全部合成压力
[所有客户端] 纯浏览器，零安装
```
- ✅ 零安装彻底、拓扑最简单、稳定
- ✅ 服务器已有 GPU（实测 `device=cuda`），可承受小队规模
- ❌ 压力全在服务器；人多了会排队
- 工程量：**小**（现状接近完成，只需补"合成归属可视化 + 队列/在线状态提示"）

### 方案 B：服务器兜底 + 可选"加速机"（推荐，最贴合你的两个诉求）
```
[服务器]      Foundry + 引擎  ← 默认引擎机(零安装玩家都用它)
[GM 电脑]     可选装引擎      ← 在分配器里指定"我的语音用我这台"
[玩家A 电脑]  可选装引擎      ← 指定"玩家A的语音用A自己那台"
[iPad 玩家]   无引擎          ← 分配给任意引擎机(默认服务器)
```
- ✅ 零安装是**默认**；想要更快的玩家可自愿装引擎分担
- ✅ 压力**按配置**精确指定（谁的语音用哪台）
- ✅ 目标机器离线 → 自动回落到服务器（1.6.75 已做兜底）
- ❌ 需要"引擎机清单/在线/负载"支撑（否则分配是盲选）
- 工程量：**中**（引擎能力注册 + 分配器升级 + 归属回执可视化）

### 方案 C：专用 TTS 机（服务器不跑引擎）
```
[服务器]        只跑 Foundry（不跑引擎）
[TTS 专用机]     引擎 + 开机自启，局域网/公网可达
[客户端]         零安装，通过 socket 代理或反向代理指向 TTS 机
```
- ✅ 把 GPU 负载从 Foundry 服务器剥离（服务器性能差时最合适）
- ❌ 需要 TTS 机常开 + 网络可达；HTTPS 下仍需服务器转发或反代
- 工程量：**中偏大**（要加"远程引擎地址"世界级配置 + 代理/反代说明）

## 五、我推荐：方案 B + 分三阶段

理由：
- 你的两个诉求都指向"**默认零安装，但可指定**"——方案 A 只有前者，方案 C 放弃了"服务器兜底"的简单性
- 服务器已有 CUDA，作为默认引擎机足够；想加速的机器自愿加入即可
- 1.6.75 已经把"分配 → 路由"接好，剩下的主要是**可信度**（知道谁有引擎、谁在执行）

## 六、分阶段实施计划

### P0（核心闭环，建议先做）
1. **引擎能力注册与心跳**（新）
   - 有引擎的客户端每 30s 广播一次 `{user, serverUrl, canDirect, 队列长度, 最近耗时}`
   - 汇总到世界设置 `engineNodes`（GM 可读，玩家只读）
   - 目视：分配器与设置页显示"**可用引擎机：服务器(在线/负载3) / 张三PC(在线/负载0)**"
2. **分配器升级为"选引擎机"**（改）
   - 列表显示：引擎机名、账号、在线、负载、能否直连
   - 每个说话者可选其一；默认 = 默认引擎机（服务器）
   - 指到"无引擎/离线"的机器时给出警告
3. **合成归属回执可视化**（改）
   - 每句合成后，发起端记录"由谁合成 + 耗时"；语音设置面板与🏁最终测试显示
   - 目视：能直接证明"压力确实按配置落在那台"
4. **排队/超时策略**（改）
   - 目标机忙 → 等待上限（如 8s）后转默认引擎机，避免卡住不出声
5. **零安装引导自检**（新）
   - 玩家首次使用：面板显示"当前由服务器合成（无需安装）"或"当前委托给 XXX"

### P1（体验与运维）
6. **GM 运维面板**：各引擎机在线/负载/最近任务、失败计数、一键切默认引擎机
7. **按角色分配**（可选）：不同角色用不同引擎机（例如七海在 A 机、丛雨在 B 机）
8. **引擎机自检**：一键检查（CUDA 是否可用、模型是否齐全、参考音是否合规、端口是否监听）

### P2（质量与性能）
9. **首句延迟优化**：常驻模型池 + 常用句预合成（已有基础，做统计与引导）
10. **远程引擎传输优化**：音频走静态文件（已有）→ 增加断点/压缩选项
11. **可选反向代理方案**：服务器前置 nginx/caddy，让远程引擎走 HTTPS 域名（摆脱 socket 体积限制）

## 八、验收方式（怎么证明达成）

| 目标 | 验收证据 |
|---|---|
| 零安装 | 用**玩家账号**在浏览器登录（不装任何东西）→ 能听到语音；🏁最终测试显示"代理合成，由「服务器账号」的电脑合成" |
| 压力可指定 | 分配器把某玩家指到另一台装引擎的机器 → 该玩家说话 → 最终测试显示"由「那台电脑的账号」合成"，且**服务器 CPU/GPU 占用不升** |
| 不出声即失败可见 | 指定机器离线时：报告显示"回落到默认引擎机"，不静默失败 |
| 不重复劳动 | 两台都有引擎时，只有被指定的那台执行（日志/归属回执可见）|
