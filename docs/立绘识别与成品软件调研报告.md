# 调研报告：成品软件如何"识别立绘"来用

> 问题：哪个成品软件能识别立绘（图片）自动使用？它是怎么做的？
> 调研口径：围绕"弹丸论破复刻场景（多情绪立绘 + 语音联动）"检索同类成品
> 日期：随 1.6.26 调研 · 信息来源：公开商品页/期刊/教程（见文末链接）

---

## 一、直接回答

**没有任何成品软件"在运行时识别立绘图片内容"来选图。** 行业里做"立绘随情绪/台词变化"的成品，全部走**"情绪判定 + 查表选素材"**路线——素材（表情/立绘）的情绪归属是**提前人为定义**的，不是程序看图判断的。

真正的"看图识别情绪"（视觉模型）只存在于**学术研究与 API 能力**，**没有集成进任何成品 TTS/对话软件**——但**可以离线打标**，这正是我们可以领先做的一块。

---

## 二、成品行业的三类做法

### 1️⃣ 台词/对话情绪分析 → 查预定义表情组（最接近我们的架构）
- **代表：YMM4 EmotionMaker KIT**（免费插件，下载量可观的日语成品）——**做法**：用 AI 对**台词做情感分析** → 从**作者预先按情绪组织好的表情素材组**里自动选配到时间轴。
- **要点**：
  - 表情素材**必须提前按情绪分组**（作者整理：喜/怒/哀/惊各一组）——**组定义是人工做的**
  - 运行时只做一件事：**台词 → 情绪 → 选组**（AI 只负责"判情绪"，不负责"认图"）
  - **这正是我们 1.6.26 的架构**（规则/LLM 判情绪 → 情绪候选组/文件名匹配选立绘）——**我们在游戏集成上比它更完整**（跨端同步、立绘演出、多角色包）。
- **差距**：YMM4 用户用前会先整理好表情分组；我们的丛雨立绘是纯数字编号，没有这个"人工整理"环节（所以只能按段猜）。

### 2️⃣ 参数驱动（人工调参，对话匹配靠脚本/协议）
- **代表：Live2D / VRM / Spine 动画**（VTube Studio、Live2D 教程等）。
- **做法**：角色表情是**可编辑参数**（眼角/嘴角/眉毛），作者调好一组组"参数快照"（笑/哭/怒…），**对话系统通过协议（脚本/API）按台词切换快照**。表情的"情绪含义"是作者调参时人工赋予的。
- **本质**：与第 1 类相同——**情绪到表情的映射是人工预置**，程序不识别图片。

### 3️⃣ 约定式命名（游戏行业立绘的通用习惯）
- **做法**：立绘文件按"**角色_情绪_序号**"命名（如 `murasame_angry_001.png`、`murasame_joy_001.png`），或按目录分层（`sprites/angry/`）。运行时**按命名/目录查表**，零 AI、零识别。
- **这是行业最普遍的"立绘情绪体系"**，也是我们 1.6.26 **已支持**的（文件名含 `angry/怒/笑/泪…` 自动精确匹配）。

---

## 三、"真正识别图片"的技术（存在，未集成成品）

- **视觉大模型（VLM）表情识别**：GPT-4o、Qwen-VL、DeepSeek-VL 等能直接看图判断人物情绪/表情。
- **学术验证**：*Facial Expression Recognition in Anime and Manga Characters*（MDPI Information 2025）对比了 GPT-4o 与 CNN 识别**动漫角色表情**——证明"看动漫立绘判情绪"技术上**可行**（GPT-4o 等泛化模型对动漫画风有不错效果）。
- **为什么成品不集成**：运行时逐帧调视觉模型 = 慢 + 贵 + 延迟不可控；而"人工组/查表"零延迟零成本。所以成熟软件全部走查表。

---

## 四、对我们的启示与建议（三条路线）

| 路线 | 做法 | 成本 | 效果 |
|---|---|---|---|
| **A. 约定式命名（推荐）** | 把丛雨等角色的立绘文件重命名成带情绪词（`angry_001.png`…），或按情绪分目录 | 零成本，一次性 | 1.6.26 自动精确匹配，行业标准做法 |
| **B. VLM 离线打标（自动化）** | 写脚本：配置多模态模型（GPT-4o/Qwen-VL 等）→ 扫描 `sprites/` 每张立绘判情绪 → 生成"编号→情绪"映射文件/批量重命名 | 需视觉模型 API key，一次性 | 全自动完成 A（不用手动整理） |
| **C. 手动映射（兜底）** | 你告诉我"0006-0015 是开心、0016-0030 是愤怒…"的编号段 | 零成本 | 写进角色包配置，精确生效 |

**推荐组合：A（或 B 自动生成 A）+ 我们已有的 AI 判情绪**——这就是 YMM4 那类成品的全部做法，且我们在游戏端做得更完整。
