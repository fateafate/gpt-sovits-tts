# 全面对照报告：gpt-sovits-tts（FVTT 模块）vs 成品 TTS 软件

> 对照对象：**GPT-SoVITS 官方（桌面 WebUI/API，我们引擎同源）**、**CosyVoice（阿里开源）**、**ElevenLabs（商业云标杆）**
> 场景口径：弹丸论破复刻（多角色游戏语音、GM 主持 + 多玩家、立绘演出、聊天即时发声）
> 版本：我们模块 1.6.20 · 成品信息来自公开文档（ElevenLabs Docs / GPT-SoVITS 仓库 / CosyVoice 仓库）

---

## 〇、一句话结论

**我们 mod 不是"又一个 TTS 软件"，而是"TTS 引擎的游戏集成层"**：合成能力继承 GPT-SoVITS（音质同源），但多了成品软件完全没有的**多端多人协同、聊天即发声、立绘演出联动、角色包管理**；反过来说，我们在**模型级情感、云便利、微调/生态**上不如成品——差距明确、可补。

## 二、分维度详解

### 2.1 定位与形态（本质差异）
- **本 mod**：跑在 Foundry VTT 里的**游戏语音层**——角色说话 → 自动合成 → 全员听到 + 立绘演出。脱离 Foundry 无意义。
- **GPT-SoVITS 官方**：通用**文本转语音桌面工具**——导入音频/文本，逐条合成试听。不做消息、不做多人。
- **CosyVoice**：**开源推理库**——开发者集成进自己的产品。
- **ElevenLabs**：**云 SaaS**——网页/API 按需调用。

### 2.2 合成引擎与音质
- 我们引擎就是 GPT-SoVITS（v2ProPlus 配置 + 并行推理 + 分桶），**音质与官方一致**；叠加了工程优化（并行合成长文本提速 2~4 倍、热身预合成、多模型常驻池）。
- ElevenLabs 云端大模型在**表现力/长文/多语言**上限更高（但不透明、按量计费、需上传音频）。

### 2.3 角色与音色管理
- **本 mod**：语音管理器（新建/编辑角色、主参考、10 语气槽、每槽独立 ref+立绘）、.char 角色包（zip 结构：character.yaml + models + sprites + speech）、导入分片（≤8GB）、立绘集导出。
- **官方**：角色目录 + WebUI 配置（参考音频/提示词），模型放 models/。
- **ElevenLabs**：VoiceLab（上传样本克隆、Voice Design 生成音色）。

### 2.4 语气/情感（本 mod 最大短板 vs 成品）
- **本 mod**：① 有情绪槽音频 → emotion_mix 参考融合（真情绪）② 单参考角色 → 1.6.20 DSP 调制（变调/变速/增益近似）③ 立绘按情绪联动。
- **GPT-SoVITS 官方**：只有参考音频驱动（单参考 = 单语气），需多段参考做情绪库。
- **CosyVoice**：**指令驱动**——"用愤怒的语气说…"自然语言控制，克隆声音也生效（模型级真实）。
- **ElevenLabs**：v3/v4 文本内嵌标签 `[angry][whispers][laughs]`，上下文/标点引导——**零样本真情感**。
- **差距本质**：我们是"参考驱动 + DSP 近似"，成品是"标签/指令驱动（模型原生）"。要补真情感需换指令驱动引擎或补情绪库。

### 2.5~2.8 我们独有（成品都没有的能力）
- **多角色多人协作**：GM 分配主持人+玩家、玩家只读；4 端（GM + 3 玩家，含 iPad HTTPS 穿透）共享同一声音。
- **聊天即发声**：发消息自动合成广播；打字即读；命令触发；跨端 flags 写回单通道（不重叠、不双播）。
- **立绘/演出联动**：消息插立绘（跟随朗读）、立绘集 40 张轮换、情绪切换立绘、HUD 快捷栏头像。
- **网络拓扑**：直连（本机/局域网）→ socket 代理（HTTPS 穿透）→ GM fetch 回传，任意拓扑出声。

### 2.9 导入导出
- .char 角色包（一键分发角色）、参考音频分片上传、chars_meta 快照（代理端拿角色）、立绘导出到 Foundry 静态。成品软件都是"单一文件/上传样本"，无"角色包分发 + 多端同步"概念。

### 2.10 部署/成本/隐私
- 我们与 GPT-SoVITS/CosyVoice 同属"免费 + 本地 GPU"；ElevenLabs 订阅制且音频上云。**本 mod 全程本地，隐私最强**。

---

## 三、关键差异总结

**我们独有的（成品软件没有）**：
1. 游戏内聊天 → 自动合成 → 全员广播播放（4 端同步）
2. 立绘演出联动（消息插图/轮换/情绪切换/HUD 头像）
3. 角色包（.char）一键分发 + 分片导入 + 多端角色快照
4. socket 代理 + HTTPS 穿透的多端网络自适应
5. 播放去重/串行队列（不重叠、不双播）

**我们缺失/弱于成品的**：
1. **模型级真情感**（ElevenLabs 标签 / CosyVoice 指令）——我们只有 DSP 近似 + 情绪槽
2. **云端便利**（ElevenLabs 免部署、按量调用）——我们是本地 GPU
3. **声音微调/定制生态**（ElevenLabs Voice Design、官方模型训练工具链）——我们用现成权重
4. **长文本/表现力上限**（云端大模型）——本地模型受权重限制

## 四、差距改进建议（对标成品）

| 差距 | 短期（现状可做） | 中期 |
|---|---|---|
| 真情感 | 情绪槽补参考音频（最真实）；DSP 参数微调 | 引擎增加指令/标签通道（CosyVoice instruct 或自训练情感分类） |
| 云端便利 | 无 | 可选远程引擎部署（API 已支持，加鉴权即可） |
| 声音定制 | 角色包多权重切换 | 接入官方模型微调/训练流程产出自有权重 |
| 表现力 | 提示词风格参数（已有 stylePrompt） | 长文分桶/分段情感标记（LLM 逐段判情绪已具备，接 DSP/情绪槽） |

**一句话**：我们的独有能力（多人协同 + 立绘演出 + 角色包分发）没有任何成品 TTS 具备；差距集中在"模型级情感"一处，路径明确（补情绪库 → 换指令驱动引擎）。
