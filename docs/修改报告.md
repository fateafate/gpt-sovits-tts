## 〇、一句话结论

**Shinsekai 的做法 = "一次 AI 决策同时定台词、立绘、语气"，无 AI 时退回角色默认参考 + 规则；我们目前的情绪是"后置判断"，AI 没真正上手改台词/选立绘。仿制方向：把朗读提示词交给 AI 让它判情绪、改台词、定立绘；没有 AI 时用现有规则/风格词/情绪槽兜底。**

## 一、Shinsekai 制作方式（源码依据：可验证）

### 1. AI 链路：LLM 输出一份 JSON，同时决定四件事
（`ai/llm/template/dialog/sections/dialog_template.py` + `json_schema.py` + `i18n/locales/en.json` L675-704）

**输出格式要求（LLM 系统提示词原文节选）**：
```json
{ "dialog": [ {
    "character_name": "角色名",
    "sprite": "两位数字立绘id, 如 01, 02",
    "speech": "台词（按角色性格/声音/背景写，语气匹配）",
    "translate": "语音语言的翻译",
    "effect": "特效标签(可选)"
} ] }
```

关键规则（i18n 原文）：
- `r_sprite`: **"sprite 必须是两位数字 id，按这句台词的语气和情绪选择"**——立绘由 AI 直接选
- `r_speech`: **"台词必须按角色性格、声音、背景写"**——AI 负责"让人物说得像人物"
- `r_format`: "只能输出 JSON，不得有任何多余文字"——一次成型，不来回补判

**vibe（氛围）模式**（`json_vibe_head_top`）：LLM 输出自由文本 `vibe: "表情/动作/氛围短语"`，运行时再解释成立绘/特效——更自然，但需要运行时解析器。

### 2. 情绪 → 语音：立绘（sprite）直接绑参考音频
（`application/chat/dialog_media/tts_generation.py` L60-110）

```python
ref_audio_path = character.refer_audio_path        # 角色主参考
if self._can_use_sprite_reference(request):         # 该立绘绑了参考音?
    ref_audio_path = sprite.voice_path              # → 用"情绪对应立绘"的参考音频
    prompt_text = sprite.voice_text
# 逐句合成: generate_tts(sentence, ref_audio_path=..., prompt_text=..., speed_factor=character.speech_speed)
```

**结论**：Shinsekai 的"情绪声音"= **立绘（情绪）绑定参考音频**（一张立绘可配一段该情绪的语音参考）。无该绑定时用角色主参考；`speed_factor` 是角色级常量，不是每句情绪调制。（这与我们"情绪槽绑参考音"是同一思路，Shinsekai 把它放到了"立绘"维度。）

### 3. 无 AI（LLM 关闭/失败）链路
- LLM 关 → 情绪为空/默认 → 默认立绘 + 角色主参考；`scene.py` 的 `emotion: str = ""` 为默认
- `ai/llm/text_processor.py`：`get_emotion_from_text` 解析旧式开头标记 `(emotion: HAPPY)`（NEUTRAL/HAPPY/ANGRY/SAD/SURPRISED/SLEEPY/RELAXED）
- 文本预处理：去动作描写（`remove_parentheses`）、语言检测、LibreTranslate 翻译到语音语言（日语）、人称替换——**这是"AI 改台词"之外的工程化保障**

### 4. 架构（支撑设计）
- 适配器工厂 `tts/tts_adapter.py`（GPT-SoVits/Kaggle/CosyVoice/Genie/Index）
- LLM 工具 `ai/tools/character_tools.py`：把"角色背景/性格/立绘 id 与情绪标注"注册成 function calling，AI 可查
- 模板系统 `ai/llm/template/`：Section/TextSection 分层拼 prompt（角色资料+历史+风格+约束）
- `application/reminders/workflow.py`：`REMINDER_EXPRESSION_STYLES`——**表达风格是作为 LLM 生成措辞的参考**（正是你说的"提示词交给 AI"）

## 附录 A：Shinsekai 立绘链路（已完成调研）

**核心：立绘不是后端关键词匹配，是 AI 直接给编号；emotion_tags 只是"提示词素材+向量索引"，行号即立绘索引。**

1. **LLM 提示词**（`llm/template_generator.py` L376-438）：输出契约含 `sprite` 字段；把角色 `emotion_tags` 原文拼进提示词（"N 个立绘：\n{emotion_tags}"）→ **AI 按台词语气情绪选 1-based 编号**
2. **编号解析**：`stream_parser.py` → `LLMDialogMessage(asset_id=sprite)`；`asset_id=-1` = 不换图
3. **调度**（`application/chat/handlers/dialog_media.py`）：`asset_lookup_strategy.lookup()` → `resolve()` → 每句产出展示消息。默认 `MessageAssetIdLookupStrategy`（原样返回编号）；semantic 模式 = vibe 文本 + **mem0 向量检索**比对每个立绘的 tag 文本排序（上次命中的优先防抖）
4. **tag_contents 算法**（`core/media/asset_tags.py`）：`"立绘 3：（巫女服）开心"` → 截掉第一个冒号及之前 → `"（巫女服）开心"`，**按行号对齐 sprite 索引**，缺行补空串
5. **兜底**：lookup 找不到 → `found=False` → **立绘保持上一张**（不跳默认图）
6. **语音绑定**：sprite 元数据带 `voice_type/voice_path/voice_text`——立绘可绑参考音频（印证：情绪=立绘=参考音三位一体）
7. **前端**：`ui.update_sprite(character, int(sprite_id)-1)`；停留时长=音频播放时长，无音频=`max(len/8, 0.5)s`；Qt 端 CrossFadeSprite 300ms 交叉淡入淡出；切换时机=每句，保持到下次切换
8. `scene.py` 的 `emotion` 字段：全仓**无 Python 代码消费**（仅序列化下发前端 story 渲染），与立绘管线无关

**对我们的仿制启示**：
- AI 选立绘 = 我们 P1-1（把角色 emotion_tags+编号表给 LLM，让它一次输出情绪+立绘编号）
- "找不到保持上一张" = 我们的兜底可以更稳（不跳默认图）
- vibe/向量检索 = P2 远期（我们无 mem0，可简化为情绪→标注匹配的软扩展）

## 附录 C：Shinsekai 情绪→TTS 语音链路（已完成调研，三路齐）

**最重要修正**：`{emotion: XX}` / `(emotion: XX)` 标记**已废弃**（`text_processor.py:33-40` 标 deprecated，全仓库 0 调用点；`remove_parentheses` 会在 TTS 前剥掉任何括号内容）。情绪的正式载体 = **sprite 编号（asset_id）+ vibe 文本**。

1. **LLM 输出**（`dialog_template.py` 五段式）：`JsonSchemaSection(10)/CharacterSection(20)/PlayerSection(25)/BackgroundSection(30)/RequirementsSection(40)`。无任何"输出情绪标记"指令；`field_requirements.py` 强制 sprite/vibe 二选一（均为 required）：
   - indexed 模式：`sprite:"两位数字编号，按台词语气和情绪自动选择最合适立绘"`（zh_CN.json r_sprite 原文）
   - semantic 模式：`vibe:"简短词语描述表情/动作/氛围"，不得填资源编号`（r_vibe）
2. **情绪知识来源**：`character.py:63-81` 把 `emotion_tags` **原文拼进 system 提示**（"N 个立绘：\n{emotion_tags}"）；`emotion_tags` 第 N 行 ↔ sprite 索引 N ↔ 该立绘的 voice 配置
3. **情绪→TTS**（`dialog_media/tts_generation.py:55-105`）：
   - `voice_type=="preset"` → 不合成直接播立绘自带音频
   - `_can_use_sprite_reference`（立绘带 reference voice）→ `ref_audio_path = sprite.voice_path`（**该立绘自己的 WAV 当参考音频**）+ `sprite.voice_text`
   - 否则 → `character.refer_audio_path` + `prompt_text`（角色级兜底）
   - **speed_factor 与情绪无关**：固定 `character.speech_speed`（角色级常量）——修正我们原先"Shinsekai 无参考音也靠 speed 变声"的理解：它靠的是**立绘参考音频**；变声来自选中的参考音
4. **无 AI / 无 TTS 行为**：
   - 无 LLM provider → `startup.py:126-127` 直接报错起不来（**我们在无 AI 时规则降级比它更可用——保留我们的优势**）
   - 无 TTS 引擎（--tts none/失败）→ `tts_manager=None` → 立绘 fallback/preset 音频直接播，否则纯文本
   - 无 ref_audio → `tts_manager.py:121-123` 静默该句（只显示文本）
   - asset_id 默认 `"-1"` → lookup 不匹配 → 立绘不变 + 退回角色级默认参考
5. **参考音频组织**（`characters.yaml` 七海千秋为例）：根级 `refer_audio_path/prompt_text/prompt_lang/speech_speed` + `sprites[]`（每项可选 `voice_path/voice_text/voice_type: fallback`，本角色每张立绘一个 WAV）+ `emotion_tags` 编号文本块（行号=sprite 序号）；映射链：emotion_tags 第 N 行 ↔ sprite 索引 N ↔ 立绘 voice 配置 ↔ LLM 选的 sprite 编号

**对我们的仿制启示（终稿）**：
- 我们的"情绪槽绑参考音"与它"立绘绑参考音"同思路；**差异在 AI 是否直接选立绘/参考音**（P1-1）
- 它的速度是角色常量；我们多做了"情绪变速+EMOTION_FX 变调"（更强，保留；将来可加开关）
- 无 AI 场景我们完胜（规则降级可用）；**P0 就做"提示词交给 AI 判情绪+润色+AI 选立绘（可选）"**，其余骨架我们已有
